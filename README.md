# OneStep — GAS × Googleスプレッドシートでスポーツクラブ運営を一元化・効率化

青森県八戸市の社会人ソフトテニスクラブ「OneStep」で実運用中の運営ツールの事例紹介です。
Google Apps Script と Google スプレッドシートで、練習予定・出欠・参加費・年会費・収支・大会申込・会員名簿を1つの画面にまとめました。

- 事例紹介ページ: `index.html`（3分で読める Case Study）
- 公開デモ: `demo/index.html`（架空データ・ブラウザだけで動く）
- CrowdWorks 用の文章: `crowdworks/`

> このリポジトリには、本番のコード全文・本番データ・ID・URL は含まれていません。公開デモのデータは完全に架空です。

## 1. OneStep とは

クラブ運営の「予定 → 出欠 → 記録 → 収支」をつなぎ、年会費・大会申込・会員名簿・バックアップまでを1つの画面で扱う Web アプリです。
管理者はスマホから練習の直後に入力し、メンバーには Google ログイン不要の閲覧用ページを配ります。

- データベースは Google スプレッドシート（クラブが自分で開けて、壊れても戻せる）
- サーバーは Google Apps Script（権限の判定・変更履歴・集計）
- 画面は単一の HTML（スマホ幅を基準に設計）

## 2. 解決した課題

以前は、練習予定・LINE リマインド・LINE 投票・参加人数・参加費・年間会費・収支・大会申込・会員情報が、LINE と複数のスプレッドシートと手作業に分かれていました。
毎回「誰が来るか」「誰がいくら払ったか」「締切はいつか」を数え直す状態で、担当者が変わると引き継げないことも問題でした。

**設計の軸は「自動化のために現場の運用を変えない」**です。メンバーが慣れている LINE 投票は残し、管理者側の転記・集計・管理だけを効率化しました。

## 3. 主な機能（R18 時点・実装済みのもの）

| 機能 | 対応する業務 | 内容 | 導入 |
|---|---|---|---|
| **ホーム / KPI** | 収支の把握 | いまの残高、今月・先月・今年度・全期間の収入／支出／収支、直近12か月の推移、年度レポート。 | R1 |
| **タスクボード** | 運営の抜け防止 | 大会の申込締切（7日前・3日前）、会費の未納、未精算の貸し借り、名簿の欠け、次の練習会の出欠人数を1か所に並べる。 | R14 |
| **練習予定管理** | 練習予定 | 月間カレンダー。月の予定をまとめて貼り付けて登録。コート面数とコート代を予定に持てる。 | R5 |
| **出欠管理** | 出欠 | 練習会ごとに、参加／欠席／未定を名前のチップで塗る。LINE 投票はそのまま、管理者が結果を写すだけ。 | R18 |
| **参加人数集計** | 参加人数 | 参加・欠席・未定・未回答を自動で数え、ホームのタスクボードにも出す。停止中のメンバーは数えない。 | R18 |
| **練習記録** | 参加費・記録 | 予定から日付・会場・時間帯を写して記録。参加メンバーは名簿からタップ、人数は±ボタン、入力しながら画面下に収支が出る。 | R1 |
| **収支管理** | 収支 | 練習会以外のお金（ボール・備品・エントリー費）も同じ収支に載る。行を開くと LINE に貼れる共有文をコピーできる。 | R1 |
| **年間会費** | 年間会費 | 年度ごとの請求・入金・未納。未納の人が上に並ぶ。入金は1回＝1行で収支にも自動で載る。 | R4 |
| **貸し借り** | 立て替え | 立て替えてもらったお金・貸したお金の台帳。残高の下に「財布の現金（見込み）」が出る。 | R4 |
| **大会申込** | 大会申込 | 要項の内容を写し、申込までの6ステップをチェック。締切は 7日前で黄・3日前で赤、Google カレンダーにも入る。 | R15 |
| **会員名簿** | 会員情報 | 本名・住所・生年月日などは本体とは別のスプレッドシートに置き、管理者だけが開ける。各行に今年度の会費状態が出る。 | R6 |
| **協会様式出力** | 協会への提出 | 協会の「登録クラブ会員名簿」と「クラブ対抗の申込書」の様式へ、名簿から自動で記入する。 | R7 |
| **閲覧用ページ** | メンバーへの共有 | Google ログイン不要の読み取り専用ページ。合言葉つき。個人情報と誰が未収かは出さない。 | R8 |
| **バックアップ** | 運営の継続 | 本体・名簿・変更履歴の3ファイルを世代印つきで複製。週1回の自動実行も設定できる。 | R5 |
| **復旧** | 運営の継続 | 削除は「隠すだけ」なので画面から戻せる。バックアップ世代からの復旧も用意。 | R5 |
| **健康診断** | データの正しさ | 台帳と収支の食い違い、スプレッドシートを直接編集した行を検出して一覧にする。 | R4 |

## 4. Before / After

| 業務 | Before | After |
|---|---|---|
| 管理場所 | LINE のトーク・投票、複数のスプレッドシート、手元のメモに分散 | OneStep の1画面に集約（予定・出欠・記録・収支・会費・大会・名簿） |
| 出欠 | LINE 投票の結果を見ながら別の場所で管理 | LINE 投票はそのまま。管理画面で参加／欠席／未定を名前チップで高速入力。未回答は自動 |
| 集計 | 参加人数・参加費を目視と手計算 | 自動集計。記録の入力中に画面下へ収支が出る |
| 記録 → 収支 | 練習の記録と収支を別々に転記 | 予定から記録へ写し、記録がそのまま収支になる（同じ予定から2件目は作れない） |
| 年会費 | 表を目で追って未納を探す | 未納の人が上に並ぶ。入金は1回＝1行で収支にも自動で載る |
| 大会申込 | 締切は記憶と紙の要項頼み | 7日前・3日前に色で警告し、Google カレンダーにも登録。申込書は様式へ自動記入（締切警告 7日前 / 3日前（本体の定数）） |
| 会員情報 | 紙と個人メモ、協会様式は手書き | 管理者限定の別ファイルで管理。協会様式へボタン1つで書き出し |
| 復旧 | 明確な復旧導線なし | バックアップ（世代印つき）・削除の復元・健康診断 |

## 6. 設計上の工夫

1. **現場の運用を変えない** — LINE 投票はそのまま。管理者が結果を見ながら名前をタップするだけで、集計と記録が進む
2. **お金の真実は1か所** — 収支を持つシートは2つだけ。会費の入金や貸し借りの精算は、そこへ自動で1行ずつ載る（二重計上が起きない）
3. **戻せることを先に作る** — 変更履歴・削除の復元・バックアップ・健康診断を、便利機能より前に実装
4. **保存の再送に強い** — 通信が切れて同じ保存をもう一度押しても二重登録にならない（操作 ID で収束）
5. **スプレッドシートの直接編集を検知** — 行の印が合わない行は保存時に止まり、健康診断に「承認」の入口が出る
6. **個人情報の分離** — 本名・住所・生年月日は管理者限定の別ファイル。閲覧用ページには個人情報と「誰が未収か」を出さない

## 7. テスト・安全性

- 自動テスト **496 件**（お金の計算・再送の収束・画面とサーバーの計算の同形・権限・履歴のフェイルクローズなど）
- Google ログインによる管理者の制御、変更履歴、論理削除、行ハッシュ、世代印つきバックアップと復旧、健康診断
- Git で管理し、ブランチ → テスト → 差分確認 → 本番反映前の確認 を通してから反映

## 8. 公開デモ

`demo/index.html` をブラウザで開くだけで動きます（通信しません）。

- 架空のクラブ・架空のメンバー 12 名・架空の会場のデータです
- 出欠を塗って保存すると集計が変わります。変更はブラウザの中だけで、再読み込みで元に戻ります
- Google カレンダー・Drive への書き出し、バックアップの複製は動きません（メッセージだけ出ます）

デモの作り直し（本体リポジトリを読むだけ。本体には何も書きません）:

```bash
tools/build-demo.sh ~/One-Step 88e191b   # demo/index.html を生成
npm install && node tools/shoot.js             # スクリーンショット 6 枚（Google Chrome を使用）
node tools/build-site.js                       # content/*.json から index.html と README.md を生成
tools/check-public.sh                          # 公開前検査
```

## 9. 本番との違い

| | 本番 | 公開デモ |
|---|---|---|
| データ | クラブのスプレッドシート | 完全な架空データ |

| ログイン | Google ログインで管理者を判定 | 管理者として開いた状態 |
| 外部連携 | カレンダー・Drive・バックアップが動く | 動かない（メッセージのみ） |
